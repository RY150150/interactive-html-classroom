# 锚点、高亮与滚动一致性

适用于固定／粘性顶部栏、侧栏目录及长篇教学页面。保持正文位置、当前小节和导航状态一致。

## 已验证过的故障模式

浏览器锚点滚动会累计根滚动容器的 `scroll-padding-top` 与目标的 `scroll-margin-top`。两者各为100px时，目标停在距顶部约200px；若高亮仅判定 `top <= 110px`，正文已经跳到目标，高亮仍留在上一项。仅在点击回调设置高亮，之后立即让滚动监听重新计算，也无法解决。

## 实现约束

- 优先只在根滚动容器设置统一偏移，目标额外偏移为0。也可选择仅对目标设置偏移，但计算高亮时必须遵从实际最终位置。
- 统一偏移由顶部栏高度和阅读间距得到；CSS使用共享变量，JS读取解析后的计算值。手机布局、缩放和改变窗口尺寸后同步重算，不复制几组互不关联的魔法数字。
- 高亮使用文档顺序中最后一个到达阅读参考线的导航目标；设置少量像素容差。若章节容器包含小节，须区分父章状态与唯一当前小节，不把父章的 `.active` 误作当前小节的测试结果。
- 所有入口通过统一导航函数设置目标和高亮，再执行滚动。使用事件委托兼容动态生成的题目／搜索链接；保留修饰键打开链接的默认语义。
- 平滑滚动期间暂时保持目标高亮，防止途中经过的章节覆盖最后选择。快速再点时取消旧目标的定时任务，以最后一次点击为准。
- 用滚动完成事件及合理的停止滚动回退释放目标状态。处理目标已在当前位置、减少动态效果、到达文档末尾等没有普通滚动过程的情况，避免永久锁定。
- 用户滚轮、触摸或页面滚动键打断时，恢复位置跟随。不要把输入框和控件的普通键盘操作误判为滚动；侧栏自身滚动不应随意打断正文跳转。
- 浏览器前进后退、初始哈希及刷新恢复均需同步。避免原生锚点、历史监听及额外 `scrollIntoView` 互相发起多次竞争滚动。

## 验证应观察的状态

针对每个实际章节／小节，在桌面和手机尺寸分别检查：

1. 从下方点击上方目标，再从上方点击下方目标。
2. 点击后立即高亮目标，平滑滚动中仍为目标，停止后仍为目标。
3. 正文落点在顶部栏下方，高亮不存在稳定的上一项偏差。
4. 同节重复点击、快速跨节点击、跨章跳转最终选中最后目标。
5. 跳转后手动滚动到相邻节，当前项能自然跟随；打断尚未结束的滚动也能恢复。
6. 从覆盖表、搜索、速查、题目解析返回讲解均同步。
7. 带锚点打开、刷新、后退和前进保持正确；减少动态效果设置下同样成立。

自动化可逐个触发目录链接、读取对应小节的高亮和实际边界框，等待滚动结束后再次断言。另抽测真实指针点击、滚动中的状态及手机菜单关闭行为。只查URL哈希、只用固定等待时间截图或只读取父章高亮都不足以验证该问题。
